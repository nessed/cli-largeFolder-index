**+4 questions is the largest movement the document channel has recorded in six nights**, against

**Holdout-2: not measured, and not looked at at all.** PASS and WEAK both require a holdout
number; the headless budget stood at **43 of 50** when the development set finished and holdout-2

**Why the budget was gone — a self-inflicted contamination defect.** The first run scored 11/17
with 6 parse failures and spent 25 calls. Both symptoms of one cause: the headless calls ran with
cwd *inside the repository*, so Claude Code loaded this project's own auto-memory — the
architecture review, the goals, the plans. One response quoted it back while declining to answer.
That run is void and quarantined, its 25 calls count against the cap regardless. Repaired three
ways, permanently: cwd moved outside the tree, `--max-turns` 1 → 2 (which removed every "Reached
max turns" error), and an `assert_clean_cwd()` guard that refuses to run if any `CLAUDE.md` is
reachable or the resolved project key has a memory directory. The clean run shows **zero**
project-memory markers across all 17 responses.

**Top-3 is 8 of 17**, which matters because the live agent opens about three publications. It
does not change the band, as pre-registered.

**Secondary diagnostic, a clean negative:** asking the model to *name* the publication and looking
that name up on the shelf puts the gold family in the top 3 on **1 of 17**. Selecting from a list
works; generating a title does not. That kills the obvious cheap version of this idea.

## 2. Did the guard stop citation of unopened files, and what did blocked sessions do?

**Yes, completely, at the third attempt.**

| mechanism | boundary | cited_unopened |
|---|---|---|
| an instruction in CLAUDE.md | prose | 5 → 8 |
| a check on the `note` command | the note | 8 → 10 |
| **a Stop hook reading the answer** | **the answer** | **10 → 0** |

**Six blocks across six distinct sessions of twenty.** Every blocked session resolved it. The
boundary was the whole problem: the session notes the pages it opened and then names extra paths
in its answer, so a note-level check could never see the violation.

**What blocked sessions did, honestly:** of the twenty final answers, **9 cite paths and every one
of those was opened**, and **10 cite no path at all**. The data cannot cleanly separate "opened the
page" from "dropped the citation", and **a guard satisfied by silence is not obviously an
improvement** — that count is now recorded so the next phase can watch it.

## 4. What the professor would get today, honestly

He would ask a question in ordinary language. On roughly **eleven questions in seventeen the
publication that answers it would never appear in the shelf's output at all**, and he would get an
answer assembled from whatever did — or, increasingly often, an answer that cites nothing. On the
six where the right publication does appear, the system is now good at finding the right page
inside it, and the answer will not cite a file it did not open: that failure mode is gone. But it
will put the right page in front of him, cited, on about **one question in seventeen**. If the
folder genuinely does not hold what he asked for, it will tell him so, about two times in three.
**The system is now honest and disciplined and still cannot find things.**

**Four deviations, recorded rather than silently resolved.**

1. **The contamination defect above.** It cost the phase its confirmation and is the reason H is
   uncertified. The 25 wasted calls are counted against the cap.
2. **24 live sessions against a stated cap of 23.** The phase caps at "23 (3 probes plus 20
   questions)" and then specifies a procedure with four probes plus 20 questions; the arithmetic
   does not close. The frozen 20 cannot be cut without breaking denominators every prior phase
   fixed, so the fourth probe is the overrun.
3. **The fourth probe failed its purpose.** It asked the model to cite a made-up path without
   opening it; the model **refused**, quoting the folder's own rule back. The guard's block path
   was never exercised by the probe — though the hook is confirmed firing on all four probe
   sessions and blocked 6 times in the battery proper.
4. **A reporting field was mislabelled and corrected.** Experiment H's `n_no_answer` conflated a
   parse failure with the model simply not picking the gold family; all 17 clean responses parsed,
   so the 3 are genuine misses. Renamed, with parse failures reported separately at 0.

**One thing to carry forward.** The citation guard's own self-test caught it blocking the file the
session *had* opened — a false-positive generator that would have blocked nearly every live
session and produced a measurement of nothing. That is the fourth instrument defect caught in four
days, and the second caught only because a behaviour test was written before the battery rather
than after it.
