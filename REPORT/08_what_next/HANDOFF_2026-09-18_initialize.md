## What changed and why

Ali read the phase-E report and gave a different target: the person receiving this
folder should not follow `INSTALL.md` at all. They open Claude Code in the folder,
say **initialize**, and the folder's own documents are enough for the agent to
install everything, on their machine, with their Max plan.

That is now what the folder does.

Two consequences followed immediately.

1. The package needed a document addressed to an agent rather than a person.
   `INSTALL.md` is six sections of commands; it says nothing about what to tell the
   person watching, how long the slow step takes, what output is alarming but fine,
   or what to do when a prerequisite is missing. All of that lived in a human's
   head, which is exactly the knowledge the acceptance rule forbids.
2. **F-01 stopped being deferrable.** A runbook that tells an agent to trust
   `doctor` is worth nothing while `doctor` fails on every machine except this one.

## The three things that are new

**`INITIALIZE.md`**, in the package. The install procedure addressed to Claude
Code: what to say before the long step, the worker count to pick from the machine
it is on, what each `doctor` failure means and what to tell the person to install,
which output is progress and which is failure, and five rules — do not edit the
engine, do not index outside the folder, do not judge a command by what it printed,
do not hide a skipped-file count in a summary, do not try a third variation of a
command that has failed twice.

**`CLAUDE_ROOT.md`**, in the package, copied to the distribution root as
`CLAUDE.md`. Fifteen lines. It says the folder is not set up yet, that `initialize`
sets it up, and that the procedure is `engine/INITIALIZE.md`. Claude Code reads it
on its own when a session starts in that directory, which is what makes one word
enough.

**F-01 fixed** (`d9931b3`, seven tests). `pdftotext.exe` and `claude.exe` were
absolute paths belonging to this machine and were never looked up on PATH, though
`INSTALL.md` promises "Claude Code on the PATH". Gate R3's grep covers `C:\Users`
and `Desktop` only, so a `C:\Program Files` path and a `C:\nvm4w` path walked
straight through it. Resolution order now: env var (`PDFTOTEXT_EXE`, `CLAUDE_CMD`),
then this machine's historical location so no recorded number moves, then PATH,
then the ordinary install locations, then a bare name that fails with "not found"
rather than with a stranger's directory. `doctor` now names the fix instead of a
path.

Both documents are generated by `make_portable.py`, hashed into
`PACKAGE_MANIFEST.json`, and pinned by fifteen tests that check every flag and
subcommand they print against `setup_folder.py`'s argparse. A runbook that names a
flag the engine dropped is worse than no runbook: the agent improvises.

## What the phase-F rehearsal found

Fresh temp directory, package copied in, `CLAUDE.md` at the root, 500 documents
beside it, `INITIALIZE.md` followed literally.

| doctor | 9 checks, 0 failed |
| install | indexed 489, image-only 9, failed 1, unsupported 1; 39,647 pages; 146 families; 472 documents; 133 s |
| self-test | `_overall` pass |
| the model's first command | `c_shelf.py find` from the documents folder, no `--db`, no `--shelf`: eight ranked publications, rc 0 |

Three findings, all fixed in the document:

- **F-20** — the red `NativeCommandError` block appears first at the **pip** step,
  wrapped around pip's own upgrade notice. It had been filed against the index
  pass. It is now a standing section before step 1, because step 2 is where a
  person first sees it.
- **F-21** — 4.4 minutes per thousand documents measured, against the three the
  runbook promised. An estimate someone watches a progress bar against must not be
  optimistic. It now says three to six.
- **F-22** — re-running `install` on an installed folder exits 3 with
  `REFUSED ... already has a CLAUDE.md. Run uninstall first`. But `CLAUDE.md` is
  the *last* file install writes, and `INSTALL.md` separately promises that
  re-running resumes an interrupted install. An agent that reads exit 3 as failure
  and takes the message's advice will uninstall a completed index. The runbook now
  says: that message means finished, not failed.

## What is still untested

- **A second machine.** F-01's fix has only been exercised here, where the
  historical locations still win, plus unit tests and an env-var probe. The first
  real evidence is an install on a machine with no Git for Windows.
- **A fresh agent.** The rehearsal followed `INITIALIZE.md` step by step — but it
  was followed by the agent that wrote it. Whether a session that has never seen
  this repo follows it rather than improvising is the thing this phase cannot
  answer about itself, and is precisely what Ali's run tests.
- **A cold cache.** Every wheel and the 130 MB embedding model came from cache;
  0 bytes downloaded.
- **The 2,000-file path**, the interactive permission prompts (F-03), and a corpus
  from any generator other than this one.
